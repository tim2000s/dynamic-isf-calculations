Questions for the maintainers

One definition

Would AndroidAPS and Trio maintainers want a shared definition with shared test vectors? The two shadow builds already use one table.

Trio’s limits

Should this mode keep the 0.7 to 1.2 limits or have its own?

The anchor

Is 140 mg/dL the right place to pin the curve to the profile ISF, or should it be the publication’s 180 mg/dL?

The shadow value

Would either project carry the shadow value on its dev line, so that records can be collected before anything doses from it?

The existing modes remain the default throughout.

These questions are for the people who maintain AndroidAPS and Trio. The first is whether there is appetite for one shared definition of this mode, with shared test vectors, given that the two systems return values 42% apart for the same person at 200 mg/dL on defaults. The second is what Trio’s limits should do for a mode whose curve sits outside them for most of its range. The third is the anchor. The last is whether either project would carry the shadow value on its dev line. Records from real use are what the next stage needs, and nothing would dose from the value while they are collected.

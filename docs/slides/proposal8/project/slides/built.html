Written against nightscout/AndroidAPS and nightscout/Trio dev, 13 November 2026.

In shadow running the new value is calculated every cycle and stored while the existing mode carries on dosing. That was written for both systems against their dev lines. AndroidAPS stores the value as curve_sens in the loop result. Trio writes it into the reason string, for example “Curve ISF: 55→49.6”. Nothing reads either value back, and the tests check that dosing is unchanged. AndroidAPS’s 14,562 unit tests passed and so did Trio’s 998, and 13 recorded Trio decisions differ only by the new tag. Both implementations are tested against the same table of ten glucose values as the Python reference. None of it has been built for or run on a device, and none of it has been published or offered to either project.

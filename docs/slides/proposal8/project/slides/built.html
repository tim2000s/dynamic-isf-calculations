Written against nightscout/AndroidAPS and nightscout/Trio dev, 13 November 2026.

Shadow running means the new value is calculated every cycle and stored, and the existing mode carries on dosing. I’ve written that for both systems against their dev lines. In AndroidAPS the value is stored as curve_sens in the loop result. In Trio it’s written into the reason string, for example “Curve ISF: 55→49.6”. Nothing reads either value back, so dosing is unchanged, and the tests check that: 14,562 passed in AndroidAPS and 998 in Trio, and 13 recorded Trio decisions differ only by the new tag. Both implementations are tested against the same table of ten glucose values, so they agree with each other and with the reference. None of it has been built for or run on a device yet, and none of it has been published or offered to either project.
